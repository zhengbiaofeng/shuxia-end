# 书匣管理端系统开发计划

更新日期：2026-07-25

## 1. 产品边界

- 当前仓库只负责管理端，不开发用户阅读端页面。阅读端由独立项目负责，管理端只维护它所需的数据、设置和接口。
- 书籍是用户拥有的本地正版文件，只允许主动上传或扫描本地/NAS目录批量导入。
- 小说以免费小说站点采集、定时追更和内容同步为主；本地文件导入仅作为用户主动导入的补充入口。
- 漫画和有声在来源、格式和处理流程未确认前，只维护已有管理能力，不自行扩展采集或转码边界。
- 不以页面临时输入代替系统配置。跨模块选择必须引用上游模块的真实记录ID。

## 2. 跨模块数据契约

| 上游唯一数据源 | 下游消费者 | 强制契约 |
| --- | --- | --- |
| 存储管理 | 书籍上传、本地扫描、小说采集、追更、迁移 | 只提交可用存储记录ID；后端再次校验状态、可写性和业务范围 |
| 分类管理 | 书籍、小说、漫画、有声编辑与导入 | 只选择分类树返回的有效分类，不在业务页自建分类文本 |
| 标签管理 | 各内容模块 | 只使用标签记录ID；标签与分类保持独立语义 |
| 采集连接模板/规则 | 单本采集、批量发现、追更 | 管理端只允许 `novel`；执行任务保存规则、来源和目标存储引用 |
| 用户与角色 | 菜单、页面、按钮、数据范围 | 前端可见性与后端权限校验必须同时成立 |
| 任务中心与日志 | 采集、解析、迁移、清理 | 异步操作统一记录任务类型、业务ID、进度、结果和错误 |
| 系统设置 | 登录页、管理端品牌、阅读端配置接口 | 管理端只负责配置；阅读端自行消费接口，不在本仓库重复实现界面 |

## 3. 模块现状

| 模块 | 核心职责 | 当前状态 | 后续工作 |
| --- | --- | --- | --- |
| 概览 | 展示真实内容、任务和系统指标 | 已具备真实接口和可执行快捷操作 | 完整备份/恢复需另行确认产品边界；当前仅提供运行快照 |
| 存储管理 | 配置本地/NAS/MinIO、检测路径与容量、设置业务范围和默认位置、迁移 | 主链已具备 | 部署新后端后做真实盘符、MinIO和迁移联调 |
| 分类管理 | 维护各内容类型分类树 | 已具备 | 与导入、编辑页做分类ID一致性回归 |
| 标签管理 | 维护描述性标签及内容关联 | 已具备 | 检查批量绑定、删除引用和类型隔离 |
| 书籍管理 | 上传、目录批量导入、解析、封面、详情和批量操作 | 主链已具备，网络采集入口已退役 | 回归 TXT/PDF/EPUB/MOBI/AZW3 和本地/NAS路径导入 |
| 小说管理 | 网络小说列表、手动本地导入补充、章节管理 | 主链已具备 | 联调采集目标存储、封面、章节和详情一致性 |
| 采集工作台 | 小说单本识别、批量发现和任务提交 | 已收敛为小说 | 对真实站点做单本、批量、失败重试回归 |
| 追更管理 | cron计划、启停、批量操作、立即同步 | 已具备 | 验证时区、错过执行、重复订阅和目标存储变更 |
| 任务中心/日志 | 采集、解析、迁移等任务监控 | 已具备核心能力；操作日志详情、导出、清理已接通 | 继续保持任务、日志和实际结果一致性回归 |
| 用户/角色/权限 | 管理后台访问控制 | 用户详情、冻结/解冻和角色权限闭环已接通 | 继续做三类角色的权限回归 |
| 系统设置 | 站点、阅读、通知、安全、授权配置 | 通知渠道、规则、模板、任务事件发送记录和重试已接通 | 后续业务事件仍需逐类确认语义后显式接入 |
| 漫画/有声 | 内容管理 | 仅有基础列表能力 | 等来源和格式边界确认后再制定计划 |
| 用户阅读端 | 面向最终读者的书架、搜索、阅读、进度和消息 | 独立项目已实现 | 本仓库只做接口联调，不新增阅读端页面 |

## 4. 严格实施顺序

### P0：产品边界与存储闭环

状态：已完成（2026-07-23），后续作为跨模块回归基线。

- 退役书籍网络采集入口，规则和连接模板的新建/编辑仅允许小说。
- 书籍上传、本地目录导入、小说上传、单本采集、批量采集和追更统一选择存储管理记录。
- 后端校验存储业务范围；文件、封面、章节记录目标存储ID。
- 被文件、追更或进行中迁移引用的存储不可删除或修改物理连接；可以暂停写入，便于故障处理。
- 迁移任务按存储ID识别本地/NAS与MinIO，不依赖旧固定名称。

验收结果：前后端构建通过；存储 SQL 已执行并重建后端容器；本地->MinIO、MinIO->本地双向迁移、书籍上传到 `sx-book`、小说采集/追更到 `novel`、错误配置零残留和删除清理均通过真实接口与存储对象核验。验收数据已清理。

### P1：权限与设置闭环

状态：已完成（2026-07-23），后续作为权限与配置回归基线。

- 建立菜单、页面动作、后端权限字符串和数据范围对照表。
- 用管理员、内容管理员、只读审计三个角色做回归。
- 逐项验证站点、阅读、通知、安全设置的保存、读取和消费者生效行为。
- 设置页面不得只显示“保存成功”，必须验证实际下游行为。

验收条件：越权请求被后端拒绝；前端不展示无权限动作；配置修改能在唯一消费者处生效。

### P2：书籍与小说可靠性

状态：已完成（2026-07-24）。

- 建立书籍格式导入矩阵以及封面、元数据、章节解析结果基线。
- 建立小说站点适配回归样本，覆盖单本、批量、定时追更、暂停、失败和重试。
- 统一重复检测、幂等提交、部分失败结果和可恢复策略。
- 验证任务中心、存储统计和内容详情对同一次操作的数据一致性。

验收条件：重复执行不会产生脏副本；失败任务可定位、可重试；存储统计与实际文件一致。

2026-07-24 验收结果：失败诊断、异步恢复/重试、批量候选上下文、逐项检查点、暂停并发保护和启动回收均已落地。受控成功/部分失败样本验证通过；原父任务恢复不会重放已成功检查点，重复提交后书籍、订阅和章节重复数均为 0。任务、小说、订阅、章节、存储摘要和目标存储源统计一致，验收数据与存储对象已清理。

### P3：漫画与有声

状态：等待产品确认边界，未开始。

- 先由产品确认合法来源、输入格式、目录结构、转码需求和存储结构。
- 确认后再设计导入、处理、任务和阅读端接口，不复用书籍或小说流程进行猜测式实现。

### P4：管理端运维闭环

状态：已完成第二阶段（2026-07-25）。

- 用户管理接通分页筛选、详情和冻结/解冻，并保留后端禁止冻结当前用户的最终校验。
- 操作日志接通筛选、分页、详情、CSV 导出和按保留期限清理；不再展示后端未提供的成功状态或 IP。
- 通知设置拆分为渠道、规则和模板三层管理，并提供真实测试发送；规则页面明确不等同于业务事件已经自动接入。
- 通知事件首批只接入 `task.completed` 和 `task.failed`。任务日志提交后持久化发送记录并异步发送，支持失败诊断、补偿和手动重试；暂停、终止、恢复和重试等管理动作不会冒充失败事件。
- 通知规则中的事件、渠道、模板和自定义接收用户由前后端共同校验。事件选项来自后端事件目录，页面不允许自由输入未实现的事件编码。
- 数据库升级只提供两个任务模板和发送记录权限，不创建默认规则，避免升级后意外向全部用户发送消息。
- 概览快捷操作区分导航动作和直接执行动作；危险存储清理只进入存储管理页面执行确认。
- 原“系统备份”改为“运行快照”，明确不包含数据库、内容文件和恢复能力。
- 建立 Vitest 基线，覆盖快捷操作元数据、用户活动、操作日志和通知配置适配。

后续候选：根据真实运营需求逐类确认并接入更多业务事件；完整备份/恢复必须先确认范围和恢复策略，不能基于当前快照接口直接扩展猜测。

## 5. 每次改动的回归门槛

1. 先确认模块边界和上游唯一数据源。
2. 列出受影响的前端页面、接口、数据库字段、任务和日志。
3. 前后端同时校验跨模块ID，禁止只依赖前端下拉框。
4. 检查新增、编辑、删除、禁用、迁移和历史数据兼容。
5. 前端执行 `npm run build`；后端至少编译 `:sx-book`，共享行为变更时打完整启动包。
6. 对关键页面做桌面和窄屏检查；对存储和任务做真实数据联调。
7. 更新项目状态和后端交接文档后，才进入下一批开发。
